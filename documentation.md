# Documentation

Documentation isn’t a pointless uphill battle, you’re just being lazy and don’t care.

Good documentation is what keeps teams aligned, reduces repetition, and scales understanding.  
Bad documentation (or none at all) creates confusion, inconsistency, and wasted effort.

> *A picture is worth 1,000 words, a link to documentation is worth 10,000.*


### **Organization**
Keep things structured and intentional.  
Separate **planning/design docs** (what *should be*) from **current state docs** (what *is*).  
Design evolves, or is not fully implemented, the current state documentation needs to stay truthful.


### **Discoverability**
Documentation is only as good as it is **findable**.  
Organize docs to make it easy to search and navigate.  
If people can’t find it, it doesn’t exist.


### **Referential**
Don’t repeat concepts the same information across documents.  
**Link** to other documents, wiki-style.  
Avoid duplication so there’s a single source of truth.  



### **Usability**
If someone asks a question that’s documented, **respond with a link**.  
If the documentation doesn’t exist, **create it**, then respond with that link.  

> **Respond with documentation. links or it didn’t happen.**
